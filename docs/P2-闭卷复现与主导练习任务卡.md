# P2 闭卷复现与主导练习任务卡

> 目的：把已经完成的项目从“跟着指导做过”转化为“自己能独立设计和解释”。

## 使用规则

1. 先自己执行，不先问完整答案。
2. 卡住时记录：哪个命令、什么报错、你判断问题在哪一层。
3. 每完成一张卡，再对照仓库中的既有实现和报告。
4. 能复述流程，比能复制命令更重要。

---

## 任务卡 A：资产发现复现

### 目标

在不看旧命令的情况下，完成一次小范围资产发现。

### 要求

1. 在 `p2-mgmt` 上确定 host-only 网段。
2. 扫描 `192.168.10.0/24`，找出在线主机。
3. 对 `192.168.10.11-13` 做服务版本识别。
4. 记录每台主机开放端口和 SSH 版本。
5. 用一句话说明“为什么漏洞扫描前要先做资产发现”。

### 验收

- 三台 target 均能被发现。
- 能解释 `nmap -sn` 和 `nmap -sV` 的区别。
- 能说明扫描范围为什么必须限制在实验内网。

---

## 任务卡 B：GVM 扫描流程复现

### 目标

独立创建一套漏洞扫描任务。

### 要求

1. 创建一个新的 SSH Credential。
2. 创建一个只包含 `192.168.10.13` 的 Target。
3. 创建扫描任务，选择：
   - OpenVAS Default Scanner
   - Full and fast
   - 正确的 Port List
4. 在启动前解释以下字段：
   - Credential
   - Target
   - Port List
   - Scan Config
   - Schedule
5. 检查 Feed Status 是否全部为 Current。

### 验收

- 能解释认证扫描和无凭据扫描的区别。
- 能说明为什么扫描前要检查 Feed Status。
- 能说明哪个字段决定“检查什么”，哪个字段决定“检查谁”。

## 任务卡 C：漏洞结果分析

### 目标

不完全依赖助手，独立判断扫描结果。

### 要求

打开加固后 CSV，找出以下内容：

1. 严重等级分布。
2. 三台主机共同存在的前三类问题。
3. 哪些问题可以通过 Ubuntu 包更新解决。
4. 哪些问题属于 SSH 配置问题。
5. 哪些问题属于宿主机或虚拟化环境限制。

### 验收

- 能区分“真实漏洞”“配置问题”“残余风险”。
- 能说明为什么不能看到 Medium 就全部直接修复。
- 能写出一段漏洞闭环描述。

## 任务卡 D：自己写一个小型 Ansible 加固任务

### 目标

不再复制完整剧本，自己写一个安全、幂等、可验证的小剧本。

### 实验目标

为三台 target 增加两个内核安全参数：

```text
kernel.dmesg_restrict = 1
kernel.kptr_restrict = 2
```

### 要求

1. 新建一个小剧本文件，不要直接修改原有大剧本。
2. 部署一个独立的 sysctl 配置文件。
3. 执行 `sysctl --system` 使配置生效。
4. 先只对 `p2-target-1` 执行。
5. 验证两个参数的实际值。
6. 第二次执行时尽量保持幂等。

### 提示

需要用到：

```text
copy
command
become
--limit
--diff
```

### 验收

- 三台主机最终都能看到正确参数。
- 能解释为什么先测一台。
- 能解释“幂等”是什么意思。
- 能复述 `copy`、`command` 和 handler 的作用。

## 任务卡 E：SSH 配置故障排查

### 目标

练一次“配置写错但不影响生产连接”的排错。

### 要求

1. 在 `/tmp` 创建一个故意写错的 SSH 配置片段。
2. 使用 `sshd -t -f` 做语法检查。
3. 根据报错定位错误行。
4. 修复为合法配置后再次检查。
5. 全程不要重启 SSH 服务。

### 验收

- 能说出 `sshd -t` 的作用。
- 能说明为什么修改 SSH 前要先做语法检查。
- 能说明如何保留一个现有管理会话作为回滚通道。
