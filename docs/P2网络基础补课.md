# P2 网络基础补课：接口、IP、端口、Host-only 与 NAT

## 一、先记住三个层次

```text
网络接口
→ IP 地址
→ 端口
```

可以把它理解成：

```text
机器 = 一栋楼
网络接口 = 楼的不同出入口
IP 地址 = 出入口的门牌号
端口 = 出入口上的服务窗口编号
```

但端口并不是“整台机器只有一个”，而是：

```text
某个 IP 地址上的某个端口
```

完整标识通常是：

```text
协议 + IP + 端口
```

例如：

```text
TCP 127.0.0.1:443
TCP 192.168.10.10:22
```

## 二、p2-mgmt 的网络接口

在 p2-mgmt 中查看：

```bash
ip -br a
```

主要接口如下：

| 接口 | 地址 | 网络类型 | 用途 |
|---|---|---|---|
| `lo` | `127.0.0.1/8` | 回环 | 机器内部访问自己 |
| `enp0s3` | `192.168.10.10/24` | Host-only | 实验管理网络 |
| `enp0s8` | 动态的 `10.0.3.x/24` | NAT | 访问互联网 |

### `lo` 回环接口

`127.0.0.1` 不是普通的局域网地址，它是每台机器内部的回环地址：

```text
p2-mgmt 访问 127.0.0.1
=
p2-mgmt 访问自己
```

其他机器不能通过自己的 `127.0.0.1` 访问 p2-mgmt。

## 三、什么是 Host-only 网络

Host-only 网络可以理解成：

```text
主机和虚拟机之间的一条隔离实验交换机
```

当前实验网络：

```text
192.168.10.0/24
```

| 设备 | Host-only IP |
|---|---|
| Windows 主机 | 192.168.10.1 |
| p2-mgmt | 192.168.10.10 |
| p2-target-1 | 192.168.10.11 |
| p2-target-2 | 192.168.10.12 |
| p2-target-3 | 192.168.10.13 |

特点：

- 主机和虚拟机可以互相访问。
- 虚拟机之间可以互相访问。
- 默认不能访问互联网。
- 适合做隔离实验，不应承载公网攻击。

## 四、什么是 NAT 网络

NAT 网络可以理解成：

```text
虚拟机通过 VirtualBox 做的一次“出口代理”
```

p2-mgmt 的 NAT 地址类似：

```text
10.0.3.15/24
```

特点：

- 虚拟机可以主动访问互联网。
- 互联网通常不能主动连接回来。
- 主要解决“虚拟机怎么下载软件、访问外部服务”。
- 不应该把 NAT 地址当成实验服务器的正式管理地址。

一句话：

```text
Host-only = 实验室内部网络
NAT = 虚拟机访问外面的出口
```

## 五、端口到底是什么

端口是操作系统为网络服务提供的逻辑入口。

例如：

```text
TCP 22  = SSH
TCP 443 = HTTPS
TCP 9392 = Greenbone 相关端口
```

端口必须结合 IP 和监听地址理解：

```text
127.0.0.1:443
192.168.10.10:443
0.0.0.0:443
```

这三者不是同一个监听范围。

## 六、服务为什么要“监听”某个地址

服务启动时可以决定自己监听在哪里。

### 只监听回环

```text
127.0.0.1:443
```

含义：

```text
只有 p2-mgmt 自己能连接这个 443 服务
```

其他机器即使知道：

```text
192.168.10.10:443
```

也连不上，因为这个服务没有绑定到 `192.168.10.10`。

### 只监听 Host-only 地址

```text
192.168.10.10:443
```

含义：

```text
Host-only 网络内能够访问这个服务
```

那么 Windows 主机、其他 target 虚拟机都可能连接。

### 监听所有 IPv4 地址

```text
0.0.0.0:443
```

含义：

```text
所有本机 IPv4 接口都监听 443
```

这通常包括 Host-only、NAT 和回环。能访问这些 IP 的网络，就可能连接该服务。

## 七、什么叫“GVM 暴露在 Host-only 网络”

当前 GVM nginx 使用类似下面的 Docker 端口映射：

```text
127.0.0.1:443:443
```

解释：

```text
左边 p2-mgmt 的 127.0.0.1:443 = 只在 p2-mgmt 内部开放
右边容器的 443:443 = nginx 在容器中的 HTTPS 端口
```

如果改成：

```text
192.168.10.10:443:443
```

或者：

```text
0.0.0.0:443:443
```

那么 GVM 就会监听 Host-only 地址。

这时，只要网络可达、防火墙允许：

```text
192.168.10.1
192.168.10.11
192.168.10.12
192.168.10.13
```

都可能尝试访问 GVM 控制台。

这就是“暴露在 Host-only 网络”的含义：

```text
不是只有主机能访问
而是整个可路由到该地址的网络都可能访问
```

## 八、绑定地址和防火墙是两回事

监听地址决定：

```text
服务有没有在这个 IP/端口上开门
```

防火墙决定：

```text
谁可以通过这个门
```

例如即使服务监听：

```text
0.0.0.0:443
```

UFW 仍然可以阻止大部分来源。

安全设计通常同时考虑：

```text
最小监听范围
+ 防火墙限制
+ 加密传输
```

## 九、SSH 隧道为什么不改变 GVM 监听范围

GVM 仍然只监听：

```text
127.0.0.1:443
```

SSH 隧道做的事情是：

```text
在 Windows 主机上临时打开 127.0.0.1:9444
→ 通过 SSH 进入 p2-mgmt
→ 由 p2-mgmt 自己连接 127.0.0.1:443
```

数据路径：

```text
Windows 浏览器
→ Windows 127.0.0.1:9444
→ SSH 加密隧道
→ p2-mgmt
→ p2-mgmt 127.0.0.1:443
→ GVM
```

这样 GVM 不需要暴露给其他 Host-only 主机。

## 十、观察练习

在 p2-mgmt 上执行：

```bash
ip -br a
sudo ss -lntp | grep -E ':443|:22|:9392'
```

观察：

- 哪个 IP 监听 22？
- 443 是否只监听 `127.0.0.1`？
- 9392 由哪个容器监听？

看懂这三条信息，就能理解“服务监听在哪里”和“谁能访问”之间的区别。
