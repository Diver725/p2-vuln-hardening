## 五、Ansible 复盘

### 1. 控制模型

```text
控制机：p2-mgmt
被管理机：p2-target-1/2/3
连接：SSH
执行环境：目标机 Python
操作单元：Ansible Module
```

概念映射：

```text
Inventory = 地址簿
SSH = 运输通道
Python = 执行环境
Module = 操作工具
Playbook = 可重复执行的配置剧本
```

### 2. 本次半扶练习

目标：

```text
kernel.dmesg_restrict = 1
kernel.kptr_restrict = 2
```

文件：

- `scripts/practice-sysctl.yml`
- `scripts/practice-sysctl.template.yml`

结构：

```text
Play
├── hosts: targets
├── become: true
└── tasks
    ├── copy
    │   ├── dest
    │   ├── owner
    │   ├── group
    │   ├── mode
    │   └── content
    └── command
        ├── sysctl --system
        └── changed_when: false
```

### 3. 执行和幂等性

第一次对 target1：

```text
copy changed
command ok
```

第二次批量执行：

```text
target1 changed=0
target2 changed=1
target3 changed=1
```

解释：

- target1 已经是期望状态，所以没有再次修改。
- target2/3 第一次写入配置，所以发生变更。
- 三台最终都满足 sysctl 参数。

### 4. 本次踩坑

- YAML 只能使用空格缩进，不能使用 Tab。
- `copy` 模块参数必须比模块名多缩进一层。
- `--syntax-check` 通过不等价于模块参数一定正确。
- `No route to host` 首先检查 target 虚拟机和 Host-only 网络。
- 加固和 UFW 后，主机存活探测可能受影响，需要调整 Alive Test 或使用 `-Pn` 验证。

## 六、漏洞结果闭环

### 已修复

| 问题 | 处理 |
|---|---|
| libsqlite3-0 旧版本 | apt 更新，复测消失 |
| SSH 弱 MAC | 收紧 MAC 算法，复测消失 |
| TCP timestamps | sysctl 关闭，复测消失 |
| ICMP timestamp | UFW 默认拒绝入站，复测消失 |

### 残余风险

```text
RETbleed
Processor MMIO Stale Data
SSB
```

原因：

- 宿主机 CPU 微码
- BIOS
- VirtualBox CPU 暴露方式

处理：

```text
记录为环境残余风险
客户机 Ansible 不强行处理
生产环境推动宿主机微码和虚拟化平台修复
```
