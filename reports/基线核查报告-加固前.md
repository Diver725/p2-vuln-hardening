## 三、主要发现

### P2-BASE-001：存在可升级软件包

**Lynis 规则**

```text
PKGS-7392
Found one or more vulnerable packages.
```

**验证命令**

```bash
ansible -i inventory.ini p2-target-1 -m shell -a "apt list --upgradable 2>/dev/null"
```

**验证结果**

p2-target-1 当前有 15 个可升级软件包，主要包括：

```text
base-files
krb5-locales
libgssapi-krb5-2
libk5crypto3
libkrb5-3
libkrb5support0
libnetplan1
motd-news-config
netplan-generator
netplan.io
python-apt-common
python3-apt
python3-distupgrade
python3-netplan
ubuntu-release-upgrader-core
```

**风险分析**

Lynis 根据软件包安全元数据判断当前系统中存在具有已知漏洞的软件包版本。该 warning 不代表这些软件包当前一定可被远程利用，但说明补丁管理没有保持最新状态。

当前 target 仅开放 22/tcp SSH，整体暴露面较小，因此风险暂时可控；在企业生产环境中应纳入补丁窗口，完成更新、回归验证和记录留档。

**整改建议**

1. 先对虚拟机打快照。
2. 执行系统更新：

```bash
sudo apt update
sudo apt upgrade
```

3. 检查是否需要重启：

```bash
test -f /var/run/reboot-required && echo reboot-required
```

4. 再次执行 Lynis 扫描，确认 `PKGS-7392` 是否消失。
5. 后续用 GVM 漏洞扫描补充 CVE 级别的验证。

**当前状态**

```text
未整改，等待 Ansible 加固阶段执行。
```

### P2-BASE-002：主机防火墙未启用

**Lynis 规则**

```text
FIRE-4512
iptables module(s) loaded, but no rules active
```

**验证命令**

```bash
ansible -i inventory.ini p2-target-1 -m shell -a "ufw status verbose" -b -K
ansible -i inventory.ini p2-target-1 -m shell -a "nft list ruleset" -b -K
ansible -i inventory.ini p2-target-1 -m shell -a "iptables -S" -b -K
```

**验证结果**

```text
UFW: Status: inactive
nftables: 无规则输出
iptables:
-P INPUT ACCEPT
-P FORWARD ACCEPT
-P OUTPUT ACCEPT
```

**风险分析**

该系统没有启用 UFW，也没有有效的 nftables 规则。iptables 默认策略全部为 ACCEPT，表示宿主防火墙没有实施实际过滤。

实验网络为隔离 host-only 网段，风险低于公网服务器；但作为企业安全基线演示，应启用最小化主机防火墙策略。

**整改建议**

1. 加固前打快照。
2. 先允许 SSH，避免启用防火墙后把自己锁在系统外面：

```bash
sudo ufw allow 22/tcp
```

3. 再启用 UFW：

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw enable
```

4. 验证 SSH 仍然可以连接：

```bash
ssh lab@192.168.10.11 hostname
```

5. 使用 Lynis 复测 FIRE-4512。

**当前状态**

```text
未整改，等待 Ansible 加固阶段执行。
```

## 四、建议分类

### 立即整改

| 类别 | Lynis 项目 | 计划 |
|---|---|---|
| 软件更新 | PKGS-7392 | 使用 apt 更新并复测 |
| 主机防火墙 | FIRE-4512 | 使用 UFW 默认拒绝入站、允许 SSH |
| SSH 加固 | SSH-7408 | 禁用 X11/Agent 转发、关闭 TCPKeepAlive、限制 MaxAuthTries/MaxSessions 等 |
| 登录防护 | DEB-0880 | 安装并配置 fail2ban |
| 密码策略 | AUTH-9229、AUTH-9230、AUTH-9262、AUTH-9286 | 配置密码质量、哈希轮数和有效期 |
| 内核安全 | KRNL-5820、KRNL-6000 | 禁用 core dump，检查 sysctl 基线 |
| 审计与统计 | ACCT-9626、ACCT-9628 | 启用 sysstat 和 auditd |

### 计划整改

| 类别 | Lynis 项目 | 计划 |
|---|---|---|
| 系统服务 | BOOT-5264 | 按需评估并加固 systemd 服务 |
| 文件完整性 | FINT-4350、PKGS-7370 | 评估 AIDE 或 debsums |
| 文件权限 | FILE-7524 | 根据 Lynis 日志逐项修正 |
| 恶意软件检测 | HRDN-7230 | 评估 rkhunter、chkrootkit 或 ClamAV |
| 日志外送 | LOGG-2154 | P3/Wazuh 阶段接入集中日志 |
| 法律横幅 | BANN-7126、BANN-7130 | 添加未授权访问警告 |
| 补丁管理辅助 | PKGS-7394 | 评估 apt-show-versions |
| APT 操作辅助 | DEB-0810、DEB-0811 | 评估 apt-listbugs、apt-listchanges |
| 临时目录隔离 | DEB-0280 | 评估 libpam-tmpdir |
| 名称解析 | NAME-4028、NAME-4404 | 配置主机名和 FQDN 解析 |

### 不适用或暂缓

| Lynis 项目 | 原因 |
|---|---|
| BOOT-5122（GRUB 密码） | 实验环境优先级低，可能影响故障恢复，暂缓 |
| FILE-6310（独立分区） | 当前虚拟机分区结构固定，重建成本高，标记为不适用 |
| USB-1000（禁用 USB） | 虚拟机环境价值有限，暂缓 |
| NETW-3200（禁用 dccp/sctp/rds/tipc） | 需确认内核模块依赖后再决定，暂不直接禁用 |
| LYNIS 版本较旧 | 可作为维护建议，不属于目标主机漏洞 |
| TOOL-5002（自动化工具） | 当前已使用 Ansible，本项可视为已满足管理目标 |

## 五、加固计划

加固前必须先完成快照，之后按以下顺序执行：

1. 系统补丁更新。
2. 主机防火墙启用。
3. SSH 安全配置。
4. fail2ban 登录防护。
5. PAM 密码策略和账号策略。
6. core dump、sysctl、auditd、sysstat。
7. 文件权限和可选项按需处理。
8. Lynis 二次扫描。
9. GVM 漏洞扫描。
10. 生成加固前后对比报告。
