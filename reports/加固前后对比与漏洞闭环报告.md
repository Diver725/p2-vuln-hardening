### 2. SSH 弱 MAC 算法

**加固前**

```text
umac-64-etm@openssh.com
umac-64@openssh.com
```

**加固动作**

部署 `/etc/ssh/sshd_config.d/99-p2-hardening.conf`，显式配置 MAC 列表并排除弱算法：

```text
hmac-sha2-512-etm@openssh.com
hmac-sha2-256-etm@openssh.com
umac-128-etm@openssh.com
hmac-sha2-512
hmac-sha2-256
umac-128@openssh.com
```

重新加载 SSH 并验证：

```text
macs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com,
umac-128-etm@openssh.com,hmac-sha2-512,hmac-sha2-256,umac-128@openssh.com
```

**加固后**

```text
SSH 弱 MAC 算法漏洞消失。
```

结论：

```text
已修复。
```

## 四、剩余问题

加固后剩余 9 条 Medium，均为三台主机共有的 CPU 侧信道问题：

| 问题 | CVE | 主机数 |
|---|---|---:|
| RETbleed 缓解缺失 | CVE-2022-29900、CVE-2022-29901 | 3 |
| Processor MMIO Stale Data 缓解缺失 | CVE-2022-21123、CVE-2022-21125、CVE-2022-21166 | 3 |
| SSB 推测存储绕过缓解缺失 | CVE-2018-3639 | 3 |

验证环境：

```text
CPU：Intel(R) Core(TM) i5-10300H
内核：6.8.0-139-generic
内核参数：未设置 mitigations=off
```

关键结果：

```text
retbleed: Vulnerable
mmio_stale_data: Vulnerable: Clear CPU buffers attempted, no microcode
spec_store_bypass: Vulnerable
```

### 判断

这些结果来自宿主机 CPU 微码、BIOS 和 VirtualBox 的 CPU 暴露方式。客户机内部无法通过普通软件包更新或安全配置直接消除。

### 当前处置

```text
记录为残余风险
不在客户机内强行掩盖
建议生产环境更新宿主机 BIOS/CPU 微码并重新评估虚拟化平台
可在 GVM 中对实验结果创建 Override，但必须保留原因和证据
```

## 五、Ansible 加固内容

本次剧本完成了：

- 系统安全更新
- `libsqlite3-0` 修复
- SSH MAC 算法收紧
- `PermitRootLogin no`
- `MaxAuthTries 3`
- `MaxSessions 2`
- 关闭 X11 和 Agent 转发
- 关闭 TCP timestamps
- 关闭 SUID core dump
- 启用 UFW
- 仅允许管理网段 SSH
- 安装 fail2ban
- 配置密码质量策略
- 设置密码有效期和默认 umask
- 启用 auditd 和 sysstat
- 添加登录警告横幅
